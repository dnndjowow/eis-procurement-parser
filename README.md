# Парсер закупок и контрактов

Проект автоматизирует заполнение Excel-файлов по закупкам и контрактам на основе ЕИС и Word-документов.

## Установка и локальные данные

Проект проверен с Python 3.12. Команды выполняются из корня проекта.

```bash
python3 -m venv venv
source venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows активируйте окружение командой `venv\Scripts\activate`.

Для запросов к моделям через OpenRouter скопируйте `.env.example` в `.env`
и задайте `OPENROUTER_API_KEY`. В macOS/Linux:

```bash
cp .env.example .env
```

Ключ требуется для вызова моделей в `test.py`; обычные парсеры ЕИС используют
свои настройки. Вызовы моделей отправляют текст документов в OpenRouter
и могут расходовать средства аккаунта. Параметры экспериментов доступны через
`python test.py --help`.

Рабочие Word-документы, Excel-файлы, отчёты и эталоны реальных контрактов
хранятся только локально и исключены из Git. После клонирования папки содержат
только `.gitkeep`. Перед запуском добавьте свои документы и совместимые
Excel-шаблоны с нужными листами и заголовками. Простая пустая книга их не заменяет.
Пути задаются в `script_zakupki/settings.py` и `script_kontracts/settings.py`;
там же задаётся целевой год. Проверяйте точное имя файла, включая регистр букв:
имя основной публикации в настройках контрактов может отличаться от имени
вашей локальной книги. Путь закупок также можно передать через `--excel`.

В `certs/eis_cacert.pem` находится набор публичных сертификатов для HTTPS.
Приватных ключей в этом файле при подготовке к публикации не обнаружено.

## Основные файлы запуска

### Закупки

Проверка без записи:

```bash
python main_file_zakupki.py --check
```

Запись в Excel:

```bash
python main_file_zakupki.py --write
```

По умолчанию закупки берут Word-файлы из:

```text
files_zakupki/
```

Результат записывается в:

```text
files_excel/for_zakupki.xlsx
```

### Контракты

Запись контрактов:

```bash
python main_file_kontract.py --write
```

Контракты берут документы из:

```text
files_kontract/
files_fas/
```

Рабочий Excel:

```text
files_excel/Shapka_New.xlsx
```

Основная публикация для копирования листов:

```text
files_excel/Publikatsia_Zakupochnykh_Protsedur_V_2026_Godu.xlsx
```

## Структура папок

```text
script_zakupki/      код парсера закупок
script_kontracts/    код парсера контрактов
files_zakupki/       Word-файлы закупок
files_kontract/      Word-файлы контрактов и протоколов
files_fas/           документы ФАС
files_excel/         рабочие Excel-файлы
reports/             отчеты запусков
clear_scripts/       скрипты очистки рабочих папок
venv/                виртуальное окружение
```

## Очистка папок

Очистить Word-файлы закупок:

```bash
python clear_scripts/clear_files_zakupki.py
```

Очистить Word-файлы контрактов:

```bash
python clear_scripts/clear_files_kontract.py
```

Очистить документы ФАС:

```bash
python clear_scripts/clear_fas.py
```

Очистить отчеты:

```bash
python clear_scripts/clear_reports.py
```

## Важные правила

- Перед записью Excel-файл должен быть закрыт.
- Закупки при запуске `--write` очищают старые строки на годовых листах и заново записывают данные из `files_zakupki`.
- Для закупок даты поставки и сроки предоставления документов берутся из Word.
- Для закупок данные ЕИС берутся по номеру извещения или через ИКЗ из Word.
- Для контрактов нужны документы контракта и протокола; ФАС используется при необходимости.
- Отчет каждого запуска сохраняется в `reports/`.

## Проверка без API

```bash
python -m unittest discover -s tests -p 'test_*.py'
```

Тесты создают временные примеры и подменяют обращения к моделям.
Одна проверка требует локального `tests/gold/contracts_v1.json` и пропускается,
если его нет. Сам файл и сопроводительное описание с данными контрактов
исключены из Git; локальная оценка по ним остаётся доступна.

## Публикация на GitHub

`.gitignore` исключает ключи, виртуальное окружение, рабочие документы,
заполненные таблицы, отчёты и локальные эталоны. Исключение из Git не удаляет
файлы с компьютера. Публикуйте проект через Git: при ручной загрузке файлов
в браузере правила `.gitignore` не фильтруют выбранные файлы.

Для первой локальной подготовки репозитория:

```bash
git init
git add .
git status --short
git diff --cached --stat
```

Проверьте состав добавленных файлов перед первым коммитом. В нём должны быть
исходники, тесты, промпты, документация, `requirements.txt`, `.env.example`,
публичные сертификаты и пустые `.gitkeep`, а не локальные данные или `.env`.
Не используйте `git add -f` для исключённых данных. `.gitignore` не исключает
файлы, которые уже были добавлены в историю репозитория.

Лицензия пока не выбрана. Перед добавлением лицензии определите, на каких
условиях вы хотите разрешить использование кода и можете ли их установить.
